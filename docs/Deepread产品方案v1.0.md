# Deepread 产品方案 v1.0

> 2026-10-31 · 第一版：中文高质量内容，每天 5 篇，不登录
> 前几版方案与代码已全部废弃，以本文档为准

---

## 0. 一句话

**每天 5 篇中文好文章，每篇给你一个问题，带着问题去读。**

不追热点，不做信息流，不替你读。只做一件事：**把今天值得读的挑出来，并告诉你该带着什么问题去读。**

### 关键决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 内容从哪来 | **人工贴链接**为主，RSS 为辅 |
| 2 | 每天发几篇 | **5 篇**，少即是多 |
| 3 | 要不要登录 | **不登录**，第一版没有用户体系 |
| 4 | 平台存不存正文 | **不存**。只存标题、摘要、问题、链接 |
| 5 | 判断"值不值得读" | **Jev 决策模型**打分 |
| 6 | 分类 | 科技 / 历史 / 经济 / 文艺（军事不做） |
| 7 | 更新节奏 | 每天 5 篇 + 每周日一期回顾 |

## 1. 产品

### 1.1 给谁

想读点好东西、但没时间在信息流里淘的人。

- 不要求他有 RSS、不要求他会用 AI、不要求他注册
- 打开就有 5 篇，读完就关掉
- 中文，不需要读英文原文

### 1.2 和 BestBlogs 的差别

| | BestBlogs | Deepread |
|---|---|---|
| 语言 | 中英混排，英文为主 | **纯中文** |
| 数量 | 每天几十篇，按分数排序 | **每天 5 篇，定量的** |
| 阅读 | 站内阅读器 + 划线 + 伴读 | **外链跳原文**，站内只放导读 |
| 门槛 | 需要筛选、需要挑 | **不用挑，就这 5 篇** |
| 核心动作 | 阅读 | **带着问题阅读** |

**我们不做阅读器，只做"读之前的判断"和"读之后的问题"。**

### 1.3 每日体验

```
早上打开
  ↓
看到 5 张卡片
  ├─ 标题 / 来源 / 作者
  ├─ 一句话：为什么今天放它
  ├─ 100 字摘要：讲了什么
  └─ ❓ 一个问题：读之前想一想
  ↓
点标题 → 跳原文，读 10–20 分钟
  ↓
读完回来 → 点「看 AI 怎么答这个问题」
  ↓
（可选）标记「这篇值得」「这篇一般」
```

**核心是那一个问题。** 它把"随便看看"变成"去找答案"。

### 1.4 不做什么

| 不做 | 原因 |
|---|---|
| ❌ 站内全文阅读 | 正文入库 = 转载，合规性质变了 |
| ❌ 划线 / 伴读 | 同上，没有正文就划不了 |
| ❌ 登录 / 用户偏好 | 第一版不需要，也不该有 |
| ❌ 无限信息流 | 每天 5 篇，定量供应 |
| ❌ 时政 / 军事 | 合规风险最高，且质量最难保证 |
| ❌ 英文源 | 目标是大众化，英文是门槛 |

## 2. 内容

### 2.1 输入方式：粘贴框优先

**第一版不写爬虫去"发现"文章，而是你贴链接，系统加工。**

```
┌──────────────────────────────────┐
│  粘贴链接（支持公众号 / 网页）      │
│  [ https://mp.weixin.qq.com/... ]│
│                        [ 添加 ]  │
└──────────────────────────────────┘
```

为什么这样设计：

1. 中文高质量内容大量在公众号里，**没有公开接口**，自动发现做不到
2. 你每天花 5 分钟贴 5 条，比维护 20 个抓取器可靠得多
3. 由你决定"今天读什么"，这本身就是编辑判断，不该交给算法

RSS 只作为辅助：科技类有几家媒体有稳定 feed，可以半自动进候选池，但**最终发哪 5 篇仍由你定**。

### 2.2 各类源能不能抓

| 源类型 | 举例 | 单篇正文 | 批量发现 |
|---|---|---|---|
| 科技媒体（有 RSS） | InfoQ、量子位、少数派、开源中国、钛媒体 | ✅ 稳定 | ✅ |
| 独立博客 / Substack | 个人站 | ✅ 最稳 | ✅ |
| **微信公众号** | 单读、国家人文历史、晚点LatePost | ⚠️ **单篇能抓，批量不行** | ❌ |
| 知乎专栏 / 回答 | — | ❌ 反爬强，多半失败 | ❌ |
| 豆瓣书评影评 | — | ⚠️ 要登录 cookie | ❌ |
| 付费墙媒体 | 财新、FT | ❌ | ❌ |

### 2.3 四个类目的现实路径

| 类目 | RSS 生态 | 现实做法 |
|---|---|---|
| **科技** | ✅ 好 | RSS + 贴链接都行 |
| **经济** | ⚠️ 一半（经济观察报、界面有；财新 FT 付费墙） | 以贴链接为主，公众号（晚点、饭统戴老板） |
| **历史** | ❌ 几乎没有 | **只能贴公众号**（国家人文历史、短史记） |
| **文艺** | ❌ 几乎没有 | **只能贴公众号**（单读、理想国、看理想） |

**结论：粘贴框是这个产品的一等公民，不是临时方案。**

### 2.4 三类条目

| 类型 | 抓到什么 | 展示 |
|---|---|---|
| **A 全量** | 正文 + 标题 + 账号 + 字数 | 完整卡片：摘要 + 问题 |
| **B 仅元数据** | 标题 + 账号（没正文） | **灰色卡片**：标题 + 账号 + 「未获取正文」，无摘要无问题 |
| **C 失败** | 连标题都没有 | 不入库，提示"这条抓不到" |

B 类同样进列表、同样分类——**因为账号名本身就是很强的类别信号**。

### 2.5 分类：三级兜底

```
① 账号映射表（人工维护 30 个账号，命中率最高）
   "国家人文历史" → 历史
   "晚点LatePost" → 经济
   "单读"        → 文艺
   "量子位"      → 科技
        ↓ 未命中
② Jev 判断（输入：标题 + 账号名 + 描述片段）
   choices: ["科技","历史","经济","文艺","其他"]
        ↓ 置信度低
③ 归入「其他」，后台一键改
```

**大类之下再挂主题小类**（如科技下的「DeepSeek」「大模型」「芯片」），
第一版由 Jev 从标题里抽 1–3 个关键词做标签，人工可改。

## 3. AI 加工

### 3.1 流水线

```
粘贴链接
  ↓
抓取（fetch + Readability，10 秒超时）
  ├─ 成功 → A 类
  └─ 失败 → 只留标题/账号 → B 类
  ↓
Jev 判定（一次调用，问三个问题）
  · worth     值不值得读（0–5 分）
  · category  归类
  · kind      深度 / 快讯 / 通稿 / 评测
  ↓
A 类才继续：
  摘要（LLM，100 字）+ 一个问题（LLM）
  ↓
你确认 → 发布（每天 5 篇）
```

**正文用完即弃，不落库。** 问答时按需重新抓取；抓不到就用摘要回答。

### 3.2 Jev 判定

一次请求问三个问题，`state` 的 token 只算一遍：

```json
{
  "model": "jev-1.14.0",
  "state": {
    "title": "27 岁程序员获无限 Token，挑战两个月重写思科 98% 的遗留代码",
    "account": "InfoQ 中文",
    "excerpt": "……正文前 4000 字（B 类则为空）……"
  },
  "questions": {
    "worth": {
      "type": "score",
      "instructions": "这条内容值不值得一个想读点好东西的人花 15 分钟读？",
      "criteria": [
        "0 分：活动通稿、公关稿、纯营销，没有信息量",
        "1 分：快讯，只有标题价值",
        "2 分：有信息但浅，30 秒能扫完",
        "3 分：值得一读，有具体信息",
        "4 分：值得花 15 分钟，有方法、数据或独到判断",
        "5 分：强烈推荐，读完会改变认知"
      ]
    },
    "category": {
      "type": "choice",
      "choices": ["科技", "历史", "经济", "文艺", "其他"]
    },
    "kind": {
      "type": "choice",
      "choices": ["深度", "快讯", "通稿", "评测"]
    }
  }
}
```

返回：

```json
{ "data": { "answers": {
    "worth":    { "score": 3.8, "confidence": 0.81 },
    "category": { "score": 0, "confidence": 0.94 },
    "kind":     { "score": 0, "confidence": 0.88 }
} } }
```

规则：

- `worth < 2.0`：默认不发，你可以手动放进来
- `worth ≥ 4.0`：标记为「本周推荐」候选
- `kind = 通稿/快讯`：即便分数高，也降级显示
- 模型**固定 `jev-1.14.0`**，不用 `jev-latest`，保证同一篇判定可复现

### 3.3 摘要规范

| 项 | 规则 |
|---|---|
| 长度 | **100–120 字**，超过就砍 |
| 内容 | 讲了什么 + 最有价值的那一点，**不评价** |
| 禁止 | 「本文介绍了」「作者认为」这类空话开头 |
| 失败 | 抓不到正文 → 不生成摘要，B 类灰卡 |

摘要不是让你省掉阅读，是让你判断要不要读。**写满 300 字就等于替用户读了，那样他不会点。**

### 3.4 问题规范（这是产品的灵魂）

问题必须满足三条：

1. 答案在文章里，读完能找到
2. 指向「所以呢」，不指向「是什么」
3. 一句话，不超过 30 字

| 类型 | 反例（废） | 正例 |
|---|---|---|
| **取舍型** | 这篇文章讲了什么？ | DeepSeek 把价格打到十分之一，其他厂商还剩哪几条路？ |
| **反常识型** | 请总结全文 | 如果开源真能赢，为什么英伟达毛利率还在涨？ |
| **因果型** | 本文的主要观点是什么？ | 同样的模型，凭什么这家公司能便宜十倍？ |
| **边界型** | 作者想表达什么？ | 这套方法在什么情况下会失效？ |

**提问的要求写进 Prompt**：禁止「本文」「请总结」「什么是」开头；必须是一个可以用一句话回答、但需要读完才能答的问题。

### 3.5 「看 AI 怎么答」

卡片底部有一行：

```
读完了？[ 看 AI 怎么答这个问题 ]
```

点开 → 调用 LLM，输入是「问题 + 正文（重新抓取）」，输出 3–5 句话的答案。

这个按钮有两个作用：

1. 给用户一个读完的理由（想知道答案）
2. **给你一个"读完了"的信号**——不登录也能埋点

## 4. 每日与每周

### 4.1 每日

| 环节 | 谁做 | 时间 |
|---|---|---|
| 贴链接（5 条） | 你 | 5 分钟 |
| 抓取 + Jev + 摘要 + 问题 | 系统 | 1 分钟 |
| 过一眼，改改措辞，发 | 你 | 5 分钟 |

**每天 10 分钟。** 这是这个产品真实的人力承诺。

### 4.2 每周日：一期回顾

```
从本周 25 篇里挑 3 篇「值得再读一遍」
  ├─ 每篇一句：为什么值得再读
  ├─ 一段 200 字的本周观察（AI 起草，你改）
  └─ 上周的 5 篇归档，可翻
```

回顾的作用不是"总结"，是**二次提纯**——把一周里真正留下的东西挑出来。

## 6. 数据模型

```sql
-- 文章（只存元数据和加工结果，不存正文）
create table articles (
  id            bigserial primary key,
  url           text unique not null,
  title         text not null,
  account       text,                 -- 公众号名 / 作者
  account_id    text,                 -- 账号标识，用于映射表
  category      text,                 -- 科技/历史/经济/文艺/其他
  topics        text[],               -- 主题小类
  word_count    int,
  cover_url     text,
  published_at  timestamptz,

  -- 抓取结果
  fetch_status  text not null,        -- full / meta_only / failed
  excerpt       text,                 -- 正文关键摘录（≤300 字，用于问答）

  -- Jev 判定
  worth         real,
  worth_conf    real,
  kind          text,                 -- 深度/快讯/通稿/评测
  judged_at     timestamptz,

  -- AI 加工
  hook          text,                 -- 一句话推荐
  summary       text,                 -- 100 字摘要
  question      text,                 -- 一个问题
  answer        text,                 -- AI 对这个问题的回答

  -- 发布
  day           date,                 -- 属于哪一天
  position      int,                  -- 1-5
  status        text default 'draft', -- draft / published / archived
  created_at    timestamptz default now()
);
create index articles_day on articles (day desc, position);
create index articles_cat on articles (category, day desc);

-- 账号 → 分类 映射（分类的第一级信号）
create table accounts (
  id          text primary key,
  name        text not null,
  category    text,
  weight      smallint default 50,    -- 账号本身的可信度
  note        text
);

-- 周报
create table weeklies (
  id          bigserial primary key,
  iso_week    text unique not null,   -- 2026-W44
  intro       text,                   -- 200 字观察
  picks       bigint[],               -- 3 篇文章 id
  published_at timestamptz
);

-- 行为埋点（不登录，按浏览器 id）
create table events (
  id          bigserial primary key,
  anon_id     text,
  article_id  bigint,
  type        text,                   -- view / click / answer_open / vote_up / vote_down
  created_at  timestamptz default now()
);
```

**注意：没有 `content` 字段。** 正文永远不落库，只保留 ≤300 字的摘录供问答用。

## 7. 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 + API | Next.js 15 + TypeScript | 一套代码，部署简单 |
| 数据库 | Postgres（Neon / Supabase 免费版） | 免费额度足够 |
| 正文抓取 | `undici` + `@mozilla/readability` | 轻量；失败就降级 B 类 |
| 判定 | **Jev**（`jev-1.14.0`） | 快、便宜、输出结构化 |
| 摘要/问题/答案 | DeepSeek 或同价位模型 | 中文好、便宜 |
| 后台 | 一个受保护的 `/admin` 页面 | 不做独立后台系统 |
| 部署 | Vercel | 免费 |

**没有**：Redis、队列、爬虫集群、用户体系。

## 9. 排期

| 周 | 目标 | 交付 | 验收 |
|---|---|---|---|
| **W1** | 能贴能看 | 粘贴框 + 抓取 + 存储 + 列表页（手动分类） | 贴 5 条，页面出 5 张卡片 |
| **W2** | 能判能分 | Jev 三个问题 + 账号映射 + 自动分类 | 分类准确率 ≥ 80% |
| **W3** | 能写能问 | 摘要 + 问题生成 + 「看 AI 怎么答」 | 5 篇的问题你都想答 |
| **W4** | 能发能回 | 每日发布 + 周报 + 部署 | 连续 7 天每天 5 篇 |

**W5 决策点**：连续一周，你自己每天都点开 ≥3 篇。做不到说明选题或问题不行。

## 10. 合规

**这一版的风险控制，靠的是"不做什么"，不是"免责声明"。**

| 做法 | 说明 |
|---|---|
| 不存正文 | 抓取只用于生成摘要，用完即弃 |
| 摘要 ≤120 字 | 不构成实质性替代 |
| 引用 ≤100 字 | 注明出处，属于适当引用 |
| 只放链接 | 阅读发生在原文站 |
| 注明来源与作者 | 每张卡片都有 |
| 删除通道 | 任何来源方要求删除，立即下架 |
| 不涉时政 / 军事 | 类目上直接排除 |

**关于公众号抓取**：单篇、低频、用户主动提交，风险可控；**不要**做批量抓取或自动发现，那会直接触发平台风控。

**这一版是"自用 + 小范围分享"，不是公开运营。** 真到公开那天，需要重新评估是否构成"新闻信息服务"。

## 11. 风险

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 公众号抓不到正文 | 高 | 中 | 降级 B 类灰卡，仍可点击 |
| 知乎链接抓取失败 | 高 | 低 | 同上 |
| Jev 中文判断不准 | 中 | 高 | 前 50 条人工校正，攒出你自己的阈值 |
| 问题问得平庸 | 中 | **致命** | 问题模板 + 你每天改一句；平庸就不发 |
| 每天 5 篇凑不齐 | 中 | 中 | 少于 5 篇也发，不凑数 |
| 你自己坚持不下去 | 中 | 致命 | 每天 10 分钟是硬预算，超了就减到 3 篇 |

**最大的风险不是技术，是"问题问得没意思"。** 那这个产品就退化成另一个链接聚合。

## 附：为什么不做划线（存档）

划线要求文字节点在我们自己的页面里。要做到这一点，必须把别人的正文抓下来存在自己站内——那就从"只放链接"变成了"全文转载"，性质完全不同。

BestBlogs 能做 AI 伴读和划线，正是因为它把正文搬进了站内。我们第一版不做这个交换：**宁可少一个功能，不换一个性质。**
