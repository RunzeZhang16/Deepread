# Deepread 创业草案 v1.0

> 2026-11-11 · 目标：把这个东西变成一个能持续带收入的副业项目

---

## 一、先说结论

**「每天自动更新」不等于完整产品。**

自动更新解决的是「内容供给」，但一个能赚钱的产品还需要另外三件东西：

| 要素 | 现状 | 缺口 |
|---|---|---|
| 内容供给 | ⚠️ 半自动（手动跑脚本 + 手动收录） | 定时任务 + 无人值守 |
| 复访理由 | ⚠️ 有更新，但没人知道它更新了 | 推送 / 邮件 / 公众号 |
| 付费理由 | ❌ 没有 | 需要设计 |

**现在的 Deepread 是一个「编辑工具」，不是「产品」。** 产品化的标志是：你不用每天动手，用户每天还会回来。

---

## 二、现状盘点（截至 2026-11-11）

**已经能跑的：**

- 295 个源自动召回（RSS + 列表页），1010 条候选
- DeepSeek 大众化打分，1010 条全评完
- 召回池人工收录 → 抓正文 → 摘要 + 1–3 个问题
- 正式版首页：8 篇正文 + 5 条当日速览
- 点问题 → 确认 → 和 AI 对话（基于单篇，不瞎编）
- 一键部署（`npm run publish`，6 分钟上线）

**关键的坑：**

- 线上白牌域名有「页面访问提示」中间页
- 冷启动 20–24 秒
- 数据是 JSON 快照，线上只读
- 没有用户系统，不知道谁在看

## 三、自动更新怎么做（技术方案）

### 3.1 流程

```
每天 06:30  定时触发
   ↓
① recall    抓 295 个源（约 3 分钟）
   ↓
② rank      只给新增条目打分（几十条，约 30 秒）
   ↓
③ briefs    抓当日新闻标题（约 1 分钟）
   ↓
④ 自动选稿  按分数取 Top 8 → 抓正文 + 生成摘要和问题（约 8 分钟）
   ↓
⑤ 质检      摘要/问题不合格的自动补位
   ↓
⑥ publish   部署上线
```

**关键判断：第 ④ 步要不要全自动？**

- **全自动**：省事，但会放出你不认可的文章（评分标准再准也有 10% 误判）
- **半自动**：系统生成 12 篇候选 + 推荐理由，你早上花 5 分钟勾掉 4 篇

**我的建议：先半自动。** 每天 5 分钟的编辑判断，是这个产品前 100 天的核心竞争力。等有了 500 个付费用户，再考虑全自动。

### 3.2 为什么现在做不到全自动

三个硬约束：

1. **容器会休眠** —— 云托管实例缩容到 0，里面跑的定时器跟着停
2. **数据不持久** —— JSON 存在容器里，重新部署就回滚
3. **没有账号** —— 编辑后台对所有人开放

### 3.3 改造清单

| 改造 | 做什么 | 工时 |
|---|---|---|
| 存储 | JSON → 云开发数据库（MongoDB） | 1 天 |
| 定时 | 云开发定时触发器 → 调 `/api/cron/daily` | 半天 |
| 编辑后台 | 线上只读 + 一个口令进入编辑模式 | 1 天 |
| 推送 | 邮件（每天 7:00 发）或公众号模板消息 | 1–2 天 |

**合计 3–4 天，之后每天你只需要 5 分钟审稿。**

## 四、靠什么赚钱

### 4.1 四条路，按现实性排序

| 模式 | 客单价 | 难度 | 说明 |
|---|---|---|---|
| **① B 端信息简报** | 2000–20000 元/年 | 中 | 给企业/团队做「每日行业简报」，可定制源和关键词 |
| **② C 端订阅** | 9.9–19.9 元/月 | 高 | 需要内容品牌，付费率通常 1–3% |
| **③ 私域 + 社群** | 99–299 元/年 | 中 | 微信社群 + 每周直播/共读，卖的是陪伴 |
| **④ 广告/赞助** | 500–3000 元/篇 | 低 | 需要粉丝量，且伤害体验 |

### 4.2 我的判断

**C 端订阅在中国极难做。** 原因很实在：

- 愿意为「信息筛选」付费的人，通常已经在用得到、小报童、知识星球
- 免费替代品太多（今日热榜、Readhub、各种周报）
- 9.9 元/月 × 100 人 = 990 元/月，还不够一台服务器的心理成本

**B 端才是这个形态的甜点。** 因为：

- 企业愿意为「省时间」付钱，客单价是 C 端的 100 倍
- 「每天 8 篇 + 摘要 + 问题」这套东西，本质是**情报简报**
- 你的技术栈（多源召回 + LLM 提炼）正好是 B 端最难自建的部分

**建议：C 端做品牌和口碑，B 端做收入。**

### 4.3 第一个付费产品长什么样

```
《Deepread 行业日报》
- 每天早上 7:30 邮件送达
- 8 条精选 + 3 条速览，每条 100 字摘要
- 针对客户行业定制（AI / 消费 / 医疗 / 出海……）
- 定价：3000 元/年（小团队） / 12000 元/年（企业，含关键词定制）
```

**先找 3 个客户。** 3 个客户 = 9000 元/年，覆盖全部成本，且验证了需求。

## 七、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **版权** | 高 | 现在只存标题/摘要/链接，不存全文，这是安全姿势；千万别做全文转载 |
| 微信封号/限流 | 中 | 不依赖单一渠道，邮件 + 站内 + 公众号三条腿 |
| LLM 成本失控 | 低 | 已做增量打分，每天只算新增几十条 |
| 内容同质化 | 中 | 差异化在「问题」和「对话」，不在选文 |
| 你时间不够 | **高** | 这是副业最大的风险：一旦每天要花 1 小时，就会放弃 |

## 八、90 天行动计划

**第 1–2 周：把「自动」做出来**
- 换存储、加定时、做后台
- 目标：7 天不碰电脑，内容照常更新

**第 3–4 周：把「读者」做出来**
- 邮件订阅 + 公众号同步
- 目标：30 个订阅

**第 5–8 周：把「钱」问出来**
- 做企业样刊，找 10 家公司聊
- 目标：1 个付费客户，或者 3 个"太贵了"的反馈

**第 9–12 周：决定去留**
- 如果拿到 1 个客户 → 加码，做多行业版本
- 如果 30 个订阅者次日打开率 < 15% → 说明内容不行，回头改内容
- 如果 0 付费 + 低打开 → 止损或者彻底转向（比如做工具而不是做媒体）

## 十、C 端和 B 端怎么兼顾（补充）

### 10.1 先说结论：它们不是两个产品，是同一个引擎的两个配置

```
                ┌─────────────┐
                │  召回（共享）│  抓 295 个源，1010 条候选
                └──────┬──────┘
                       │
                ┌──────▼──────┐
                │  精排（共享）│  大众化基础分
                └──────┬──────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   profile: 今日精选  profile: AI 日报  profile: 客户甲
   （大众、多样）     （行业垂直）      （自定义关键词）
```

**最贵的环节（抓取）只做一次，筛选和生成很便宜。**

所以「B 端只推行业信息、C 端要多样」不冲突——它们是同一批候选的两种切法。

### 10.2 具体怎么切

| | C 端《今日精选》 | B 端《行业日报》 |
|---|---|---|
| 候选池 | 全部 1010 条 | 同一批，按关键词过滤 |
| 筛选标准 | 大众化：普通人读得懂 | 行业相关 + 可操作性 |
| 内容构成 | 科技/人文/商业/科学混搭 | 竞品动态、政策、技术进展 |
| 频率 | 每天 8 篇 + 5 条速览 | 每天 8 条 + 3 条速览 |
| 分发 | 网站 + 邮件 | 邮件 + PDF/Excel 导出 |
| 收费 | 免费 | 3000–12000 元/年 |

### 10.3 技术上要加什么

现在 `data/articles.json` 是一个列表。改成：

```json
{
  "articles": [
    { "title": "...", "editions": ["default", "ai-daily"] }
  ],
  "profiles": [
    { "id": "default",  "name": "今日精选", "keywords": [], "size": 8 },
    { "id": "ai-daily", "name": "AI 行业日报", "keywords": ["大模型","Agent","算力","英伟达"], "minScore": 60, "size": 8 }
  ]
}
```

改动量：**1–2 天**（在阶段 1 的存储改造里一起做，不额外增加周期）。

### 10.4 真正的冲突不在技术，在这三处

**① 品牌认知**

同一个域名，首页说「每天读点好的」，邮件说「AI 行业情报」——用户会困惑。

> 解法：C 端是主站（免费、做口碑），B 端是「Deepread 行业版」，独立邮件和落地页，但共用品牌。

**② 内容口味**

B 端要「全而快」（今天竞品发了什么），C 端要「少而精」（宁缺毋滥）。**同一个稿子不能两边都发。**

> 解法：两套筛选标准，B 端允许 60 分进（信息价值优先），C 端只放 80 分以上。

**③ 你的精力**

一个人同时维护两条线，大概率两条都做不好。

> 解法：**阶段错位**——前 3 个月，C 端"半自动免费跑着"（不投入精力），80% 时间放在 B 端销售上。等 B 端有了 3 个客户，再回头优化 C 端。

### 10.5 推荐的顺序

```
第 1 步：引擎改造（多 profile）     1–2 天
第 2 步：C 端免费跑起来（自动更新）  1 周
第 3 步：做一份「AI 行业日报」样刊   3 天
第 4 步：找 10 家公司聊，卖出去      4 周 ← 精力全在这里
第 5 步：有客户后，再扩第二个行业     视情况
```

**C 端是门面，B 端是生意。门面可以慢慢修，生意要马上去谈。**

## 十一、盈利模型（细化版）

> 第四节讲了"靠什么赚钱"，这一节讲"具体怎么收、收多少、能赚多少"。
> ⚠️ 以下数字是**基于市场常识的假设**，不是承诺。每一项都标了验证方法。

### 11.1 三个收入来源

```
① B 端行业简报（主收入，占 70%）
② C 端会员订阅（副收入，占 25%）
③ 其他（赞助/联盟，占 5%，最后做）
```

### 11.2 B 端：产品与定价

**产品形态**：每天早上 7:30 邮件送达的行业简报（PDF + 网页版），8 条精选 + 3 条速览，每条 100 字摘要 + 原文链接。

**三档定价：**

| 档位 | 价格 | 包含 | 目标客户 |
|---|---|---|---|
| **基础版** | 3,000 元/年 | 1 个行业，5 个收件人，标准关键词 | 小团队、创业公司 |
| **专业版** | 8,000 元/年 | 3 个行业，20 个收件人，关键词可定制 | 中型公司市场/战略部 |
| **企业版** | 20,000 元/年 | 定制信息源 + API 接口 + 每周电话解读 | 大公司、投资机构 |

**为什么这样定价：**

- 3,000 元 = 一个员工 2 天的工资。**只要每天帮他省 20 分钟，就值这个钱**
- 只做年付，不做月付——月付的流失管理成本会吃掉利润
- 首年 5 折（1,500 元）换案例和推荐语，第二年恢复原价

**交付成本（毛利极高）：**

| 项 | 每客户每年 |
|---|---|
| 内容生成（共享 C 端内容池，只多一次筛选） | 约 10 元 |
| 定制关键词的额外打分 | 约 15 元 |
| 邮件发送 | 约 20 元 |
| 你的时间（每周 15 分钟答疑） | 约 13 小时 |
| **现金成本合计** | **约 45 元** |

**毛利率 ≈ 98%。B 端的成本几乎只有你的时间。**

### 11.3 C 端：会员设计

**免费能看什么（足够好，才有人来）：**

- 每天 8 篇的标题 + 摘要 + 3 个问题
- 每天 3 轮 AI 对话
- 当天的速览 5 条

**付费解锁（99 元/年 或 12 元/月）：**

- AI 对话不限量（每天上限 20 轮）
- 历史归档（过去 30 天全部内容）
- 每周「本周精选册」（PDF）
- 无广告

**定价逻辑：**

| 价格 | 心理定位 | 风险 |
|---|---|---|
| 12 元/月 | 一杯奶茶，决策成本低 | 月付流失快 |
| **99 元/年** | 一天 3 毛，容易接受 | **推荐** |
| 199 元/年 | 显得专业，但转化率低 | 需要更强的内容 |

**首年主推 99 元/年**，第二年如果内容够硬再考虑 199。

**C 端的成本结构（关键）：**

| 用户类型 | 每年成本 |
|---|---|
| 免费用户（每天 3 轮对话） | 约 10 元 |
| 付费用户（每天 10 轮对话） | 约 33 元 |
| 付费用户（每天 20 轮，重度） | 约 66 元 |

**所以 99 元/年的付费用户，毛利约 66%。**

⚠️ **如果放任重度用户无限对话，单个用户成本会超过 99 元**——所以必须限流（每天 20 轮），这是设计，不是小气。

### 11.4 收入预测（12 个月）

**保守（大概率能到）：**

| 项 | 数量 | 单价 | 年收入 |
|---|---|---|---|
| B 端客户 | 3 | 3,000 | 9,000 |
| C 端会员 | 50 | 99 | 4,950 |
| **合计** | | | **13,950** |

成本约 6,000（服务器+LLM+杂项）→ **净利约 8,000**

**中性（努力可及）：**

| 项 | 数量 | 单价 | 年收入 |
|---|---|---|---|
| B 端客户 | 8 | 5,000（均价） | 40,000 |
| C 端会员 | 200 | 99 | 19,800 |
| **合计** | | | **59,800** |

成本约 8,000 → **净利约 52,000**

**乐观（需要运气+执行）：**

| 项 | 数量 | 单价 | 年收入 |
|---|---|---|---|
| B 端客户 | 20 | 6,000 | 120,000 |
| C 端会员 | 800 | 99 | 79,200 |
| **合计** | | | **199,200** |

成本约 15,000 → **净利约 18 万**

|---|---|

### 11.6 怎么卖：B 端销售流程（你的执行清单）

**第 1 周：准备**

- [ ] 做一份 3 天内容的样刊（PDF）
- [ ] 写一页介绍（解决什么问题、多少钱、怎么用）
- [ ] 列 50 家目标公司（**从你熟悉的行业开始**）

**第 2–4 周：触达**

- [ ] 每周触达 10 家（邮件 + 微信 + 朋友介绍）
- [ ] 话术（三句话）：

> 我在做一个行业简报，每天早上把你这行的 8 条重要信息做成摘要，7:30 发到邮箱。
> 这是样例，您先看三天，不收钱。
> 如果觉得有用，一年 3000，不需要了随时停。

**第 5–8 周：成交**

- [ ] 电话 15 分钟，只问三个问题：
      1. 你们现在怎么获取行业信息？
      2. 每天花多少时间？
      3. 如果有人帮你做这件事，值多少钱？

### 11.7 C 端：什么时候提示付费

不要在首页挂"开通会员"，太早。三个自然的触发点：

| 触发点 | 时机 | 文案 |
|---|---|---|
| **对话次数用完** | 第 3 轮时 | "今天的免费次数用完了，开通会员可以继续聊" |
| **想看历史** | 点"往期"时 | "过去 30 天的内容，会员可见" |
| **连续访问 7 天** | 第 7 天 | "你连续来了 7 天，要不要订阅每周精选册？" |

**转化率参考：** 触发点做得自然，免费→付费 1–3% 是正常水平。

### 11.8 定价怎么验证（别拍脑袋）

**方法一：问三个价格**

对 10 个潜在客户问同一句话：

> "如果这个东西一年 X 元，你觉得是太贵、划算、还是太便宜？"

分别用 1,000 / 3,000 / 8,000 问不同的人。**如果大部分说"太便宜"，说明你定价低了。**

**方法二：看行动不看嘴**

- 说"有兴趣"不算数
- **愿意先试用 3 天** 才算半个信号
- **愿意先付 500 定金** 才算真信号

### 11.9 收款、开票与合同

**前期（0–10 个客户）：**

- 个人收款码 / 对公转账，**手动开通**
- 不发合同，发一封确认邮件（服务内容 + 期限 + 退款条款）
- 不开票（个人），客户如果必须要票，去注册个体户

**后期（10 个客户以上）：**

- 注册个体户（0–500 元）→ 可以开普票
- 用电子合同模板（腾讯电子签，免费额度）
- 退款政策：7 天内无理由全额退

### 11.10 单位经济模型（一张表看懂）

| | B 端（基础版） | C 端（年费） |
|---|---|---|
| 年收入 | 3,000 元 | 99 元 |
| 现金成本 | 45 元 | 33 元 |
| 毛利率 | **98%** | **67%** |
| 获客成本 | 2,000 元（时间） | ≈ 0（内容） |
| 首年净利 | 955 元 | 66 元 |
| 续费后年净利 | 2,955 元 | 66 元 |
| **回本周期** | **首年** | **首年** |

**结论：B 端一个客户 = C 端 45 个会员。所以先卖 B 端。**

### 11.11 关键假设与验证时间点

| 假设 | 如果错了会怎样 | 什么时候验证 |
|---|---|---|
| 企业愿意为"信息筛选"付 3000/年 | 整个 B 端模式不成立 | 第 8 周（10 家聊完） |
| C 端付费率 1–3% | 收入低一个数量级 | 第 12 周（500 关注后） |
| 内容质量能撑住口碑 | 涨粉慢、续费低 | 第 6 周（看转发率） |
| 你每天只花 5 分钟 | 项目会被放弃 | 第 4 周（看是否疲惫） |

### 11.12 止损线（提前想好，别到时候舍不得）

| 时间点 | 如果没达到 | 就 |
|---|---|---|
| 第 8 周 | 0 个 B 端客户，且没人愿意试用 | 重做产品定位，或换客群 |
| 第 12 周 | 公众号 < 200 关注，次日留存 < 10% | 内容方向有问题，重做选题 |
| 第 16 周 | 收入 < 3,000 元 | 承认这是"自用工具"，不再投入 |
| 第 24 周 | 收入 < 10,000 元 | 停更或转让，止损 |

**止损不是失败，是把时间还给更值得的事。**
