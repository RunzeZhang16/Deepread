## 一、网址怎么规划？

**一个主域，够用。**

```
www.deepread.com     主站（C 端内容 + 会员）
（邮件发信域暂不申请，V1 不做邮件订阅）
```

- 不做 B 端专用域名（B 端方案已暂缓）
- 不分子域做"会员版"，同一个站，登录后解锁能力
- 以后如果做小程序，用同一个主体注册即可

**为什么不多买域名：** 每个域名都要备案、证书、SEO，一个人维护不过来。

## 二、要不要做成 App？

**不要。至少一年内不要。**

理由很实在：

| 渠道 | 获客成本 | 留存 | 你的维护成本 |
|---|---|---|---|
| **网页（移动端适配）** | 最低，链接就能发 | 中 | 低 |
| **邮件** | 中国用户不看邮箱 | 低 | 中 |
| **微信公众号** | 低，靠内容涨粉 | 高 | 中 |
| **微信小程序** | 中 | 高 | 中 |
| **原生 App** | **最高**（应用商店+下载） | 高 | **高**（双端+审核+发版） |

一个日更内容产品，**用户每天只需要看 10 分钟**——这种使用频次撑不起一个 App 的下载门槛。

**正确顺序：**

```
第 1 阶段：响应式网页 + 公众号      ← 现在
第 2 阶段：公众号日更 + 互推         ← 立刻开始
第 3 阶段：小程序（可选）            ← 有稳定收入后
第 4 阶段：App                      ← 大概率永远不需要
```

## 三、正式上线部署到哪里？

### 3.1 三条路的取舍

| 方案 | 备案 | 成本 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 香港轻量服务器** | ❌ 免 | 24–40 元/月 | 立刻能用、无中间页 | 速度一般，理论上有被墙风险（概率低） |
| **B. 国内云 + 备案** | ✅ 2–4 周 | 24–60 元/月 + 域名 | 速度最好、合规 | 备案要等，还要挂网站负责人 |
| **C. 腾讯云 CloudBase** | 默认域名有中间页 | 按量 | 已跑通 | 中间页 + 冷启动，不适合正式上线 |

### 3.2 推荐路径

```
现在 → 香港轻量服务器（A），一周内上线
6 个月后，有稳定收入 → 迁国内 + 备案（B）
```

**香港服务器具体配置：**

```
2 核 2G / 40G SSD / 30Mbps 峰值
Ubuntu 22.04
Docker + docker-compose
Nginx 反代 + Let's Encrypt 免费证书
```

⚠️ 注意：**不要买太便宜的"香港虚拟主机"**，要能跑 Docker 的轻量 VPS（腾讯云国际站、阿里云国际、Vultr、BandwagonHost 都行）。

### 3.3 域名与备案

- 域名：`.com` 约 70 元/年（阿里云/腾讯云注册）
- 香港服务器**不需要备案**，解析直接生效
- 如果域名在国内注册商，解析到境外 IP 通常也没问题

## 四、大模型怎么用？（最关键的工程决策）

### 4.1 三个调用点

| 场景 | 频率 | 模型 | 单次成本 |
|---|---|---|---|
| 摘要 + 问题生成 | 每天 10–12 次 | DeepSeek-Flash | ~0.01 元 |
| 候选打分 | 每天 100 条（批量） | DeepSeek-Flash（低推理档） | ~0.0003 元/条 |
| 用户对话 | 每人每天 1–3 轮 | DeepSeek-Flash | ~0.01 元/轮 |

### 4.2 架构原则

```
浏览器 → 你的服务器 → DeepSeek API
         ↑
    key 只存在服务器环境变量里
```

**四条硬规则：**

1. **Key 绝不下发到前端**（现在就是这么做的）
2. **对话限流**：每用户每天 20 轮，超了提示"明天再来"
3. **答案缓存**：同一篇文章 + 同一个问题，24 小时内直接返回缓存
4. **失败降级**：模型超时/报错 → 返回"这个问题稍后再试"，**不影响看文章**

### 4.3 备用方案

单一供应商有风险（涨价、限流、宕机）。方案：

```js
主：DeepSeek（便宜、中文好）
备：阿里通义 / 智谱 GLM（配置一行切换）
```

接口都是 OpenAI 兼容格式，切换成本几乎为零——代码里已经用 `LLM_BASE_URL` 抽象了。

### 4.4 对话成本是最大变量

文章生成和打分是**固定成本**（每天约 0.15 元），对话是**变动成本**（随用户数线性增长）。

所以：
- 免费用户：每天 5 轮
- 付费用户：每天 50 轮

## 五、成本总账

### 5.1 固定成本（每月）

| 项 | 费用 |
|---|---|
| 香港轻量服务器 2C2G | 40 元 |
| 域名（70/年） | 6 元 |
| SSL 证书 | 0（Let's Encrypt） |
| 代码托管/CI | 0（GitHub 免费） |
| **小计** | **约 46 元/月** |

### 5.2 变动成本

**LLM（按 2 元/百万输入、8 元/百万输出估算）：**

| 规模 | 每日生成 | 每日对话 | LLM 月成本 |
|---|---|---|---|
| 0–100 用户 | 0.10 元 | 1.4 元 | **约 45 元** |
| 1000 用户 | 0.15 元 | 14 元 | **约 425 元** |
| 10000 用户 | 0.2 元 | 140 元 | **约 4200 元** |

**邮件（V1 不做）：**

原方案把邮件当分发渠道，现已降级——**V1 完全不做邮件订阅**。

| 项 | 成本 |
|---|---|
| 邮件服务（Resend 等） | 0（不做） |
| 邮件模板/退订/送达率维护 | 0（不做） |

省下的不只是钱，还有**每周维护发信域、SPF/DKIM、退信处理的时间**。这些时间应该花在公众号内容上。

### 5.3 总账

| 规模 | 月成本 | 需要多少收入回本 |
|---|---|---|
| **启动期（<100 用户）** | **约 90 元** | 10 个会员（99 元/年） |
| **1000 用户** | **约 620 元** | 63 个会员 |
| **10000 用户** | 约 5000 元 | 500 个会员 |

**结论：1000 个访问用户 ≈ 需要 63 个付费会员才能覆盖成本。**

### 5.4 一次性成本

| 项 | 费用 |
|---|---|
| 域名首年 | 70 元 |
| 备案（如需） | 0 元，但 2–4 周时间 |
| 支付资质（如需） | 个体户注册 0–500 元 |
| **合计** | **< 600 元** |

                  │  (443/80)    │
                  └──────┬───────┘
                         │
                  ┌──────▼───────┐
                  │  Next.js     │ Docker 容器
                  │  (3000)      │
                  └──┬───────┬───┘
                     │       │
        ┌────────────▼──┐  ┌─▼──────────────┐
        │ SQLite/Postgres│  │ DeepSeek API   │
        │  内容 + 用户    │  │ 摘要/打分/对话  │
        └────────────────┘  └────────────────┘
                     │
        ┌────────────▼─────────────┐

        └──────────────────────────┘
                     │
              ┌──────▼──────────┐
              │ 公众号（手动/半自动）│ 每天 7:30 发布

### 6.2 数据库表

```sql

candidates   (id, source_id, title, url, published_at, score, reason, status)

subscribers  (id, email, profile_id, confirmed, created_at)
```

### 6.3 定时任务（宿主机，不放在容器里）

```bash
# crontab -e
30 6 * * * /opt/deepread/scripts/daily.sh >> /var/log/deepread.log 2>&1
30 7 * * * /opt/deepread/scripts/send-mail.sh >> /var/log/deepread.log 2>&1
```

**为什么放宿主机**：容器会重启、会休眠，宿主机 cron 不会。

## 十、获客与分发（修订版）

> 原方案把「邮件」当 C 端主要渠道，是错的。中国用户不读邮件。此处修订。

### 10.1 各渠道的真实位置

| 渠道 | 获客能力 | 留存能力 | 结论 |
|---|---|---|---|
| **微信公众号** | **强**（看一看、搜一搜、朋友圈转发） | 强（关注即订阅） | ✅ **C 端主阵地** |
| 网站 | 弱（没有自然流量） | 中 | 落地页 + 分享名片 + 搜索长尾 |
| 邮件 | **极弱**（中国用户不看邮箱） | 低 | ❌ **V1 不做** |
| 小红书 / 知乎 / 即刻 | 中（能引流，但平台限流） | 弱 | 辅助，做内容切片 |
| 微信群 / 朋友圈 | 强（熟人传播） | 中 | 冷启动第一批用户 |
| 小程序 | 中 | 强 | 第二阶段，微信内闭环 |

**结论：**

```
C 端：**公众号为主，网站为辅，邮件不做。**
```

### 10.2 C 端获客漏斗

```
公众号推文（每天 1 篇）
   │  内容是产品本身：8 篇摘要 + 3 个问题
   ▼
读者觉得有用 → 关注 / 转发
   │
   ▼
点「阅读原文」→ 网站
   │  网站上有完整版 + AI 对话
   ▼
关注公众号 / 收藏网站
   │
   ▼
（后期）付费订阅
```

**关键认知：公众号的文章本身就是获客素材。** 你不需要"推广"，你需要每天发一篇别人愿意转发的文章。

### 10.3 公众号的现实约束

| 约束 | 影响 | 解法 |
|---|---|---|
| 个人订阅号**每天只能群发 1 次** | 一天只能发一篇 | 刚好：一天一篇「今日精选」 |
| 个人订阅号**没有发布 API** | 不能全自动发 | 每天手动复制粘贴（5 分钟） |
| 认证需要企业主体或 300 元/年 | 高级接口用不了 | 前期不认证，够用 |
| 微信对站外导流敏感 | 链接可能被限 | 只用「阅读原文」位，不在正文放链接 |
| 打开率逐年下降 | 涨粉慢 | 靠「问题」设计提升互动和转发 |

**个人订阅号 vs 服务号：**

- 订阅号：每天 1 次群发，适合日更内容 ✅
- 服务号：每月 4 次群发，适合通知和支付 ❌ 不适合日更

**所以：C 端用订阅号，日更。**

### 10.4 前 100 个订阅者怎么来（冷启动）

不靠算法，靠手工：

1. **朋友圈 + 微信群**：发 3 天，看有没有人主动问"怎么订阅"
2. **垂直社群**：AI 群、产品经理群、投资人群，每天转发当天精选
3. **知乎/小红书**：把当天最好的一篇改写成短文，结尾引导
4. **互推**：找 3–5 个同类小号（1000–5000 粉）互相推荐
5. **朋友圈截图**：把"AI 对话"的截图发出去（这是别人没有的功能）

**前 100 个订阅者，预计 2–4 周，不需要花钱。**

### 10.5 公众号内容怎么生产（每天 5 分钟）

系统已经生成好：8 篇标题 + 摘要 + 3 个问题。

```
① 复制今天的 edition（脚本导出 Markdown/HTML）
② 粘贴到公众号编辑器
③ 配一张头图（可以用每日随机配图）
④ 点群发
```

**可以做到 5 分钟。** 后续如果认证了服务号，可以用 API 自动发草稿箱，连粘贴都省了。

### 10.6 修订后的成本

| 项 | 原方案 | 现在 |
|---|---|---|
| 邮件服务 | 150 元/月（1000 订阅） | **0（V1 不做）** |
| 公众号 | — | 0 |
| 服务器 | 40 元/月 | 40 元/月 |
| LLM | 425 元/月 | 425 元/月 |

**1000 用户时，月成本从 620 元降到约 470 元。**
**如果连邮件维护的人力算进去，实际省下的更多。**

### 10.7 阶段目标

| 阶段 | 渠道 | 目标 |
|---|---|---|
| 1–2 周 | 网站 + 自动更新 | 能发链接 |
| 3–4 周 | **公众号开号 + 日更** | 100 个关注 |
| 5–8 周 | 公众号 + 社群 + 互推 | 2,000 个关注、60 个会员 |

**公众号不是"以后再说"，是第 3 周就要开的。**

## 十一、公众号每天写什么

### 11.1 先纠正一个误解

**技术上完全可以把网站内容搬到公众号**——复制粘贴就行，没有任何限制。

**但不该全搬。** 原因有三：

1. **版权**：全文转载别人的文章有风险；只引用标题 + 100 字摘要 + 链接是安全的
2. **产品逻辑**：公众号看全了，谁还去网站？网站才是能对话、能订阅的地方
3. **推荐权重**：微信的「看一看」偏爱原创内容，纯摘要合集会被判定低质

**所以公众号的定位是：预告片，不是正片。**

### 11.2 公众号内容结构（每天固定模板）

```
标题：今天值得读的 8 篇（11 月 12 日）

【开头 150 字】编辑按语
  今天为什么选这些？这批文章有什么共同点？
  —— 这部分必须是原创，也是原创声明的依据

【主推 1 篇】约 500 字
  - 为什么值得读（不是复述内容，是说"它解决了什么疑问"）
  - 3 个问题
  - 一句"完整版和 AI 对话在原文链接里"

【其余 7 篇】每篇 2 行
  - 标题
  - 一句话推荐 + 1 个问题

【结尾】
  阅读原文 → 网站看完整版、和 AI 聊这篇
```

**全文约 1200–1500 字，10 分钟能写完，5 分钟能排版。**

### 11.3 为什么这个结构能涨粉

| 设计 | 作用 |
|---|---|
| **主推 1 篇而不是 8 篇** | 读者有明确入口，不会滑走 |
| **编辑按语** | 提供"人"的观点，这是 AI 产品最缺的东西 |
| **3 个问题** | 引发评论区讨论 → 提升推荐权重 |
| **其余 7 篇只给一句话** | 制造信息缺口，逼读者点"阅读原文" |
| **结尾引导到网站** | 公众号涨粉，网站做转化 |

### 11.4 内容来源与工作量

系统每天生成：8 篇标题 + 摘要 + 问题。
**你要额外写的只有：150 字按语 + 1 篇 500 字导语。**

如果连这个都不想写，可以让 DeepSeek 生成初稿，你改两句——但要保留"人味"，纯 AI 文案在微信里很难涨粉。

### 11.5 三条红线

1. **不放全文**：只放标题 + 100 字内摘要，正文链接到原文
2. **正文不放站外链接**：只在「阅读原文」位放（微信对正文外链敏感）
3. **不要日更超过 1 篇**：订阅号一天只能发一次，攒着一起发效果更好

## 十二、登录与埋点

### 12.1 第一版：不用登录

| 功能 | 要不要登录 |
|---|---|
| 读每天的 8 篇 + 速览 | ❌ 不要 |
| 点问题和 AI 对话 | ❌ 不要（匿名，按浏览器标识限流） |
| 邮件订阅 | ✅ 只要邮箱，不要密码 |
| 付费 | ✅ 需要账号 + 订单 |

**结论：V1 全站匿名可读，只在「订阅」和「付费」两个动作上要身份。**

这和现在一致，不用改。

### 12.2 埋点怎么做（无登录也能统计）

**核心思路：匿名访客 ID + 事件表。**

```js
// 首次访问生成，存 localStorage，永不上传个人信息
const aid = localStorage.getItem('dr_aid') || crypto.randomUUID();
localStorage.setItem('dr_aid', aid);
```

前端上报（用 sendBeacon，不阻塞页面）：

```js
navigator.sendBeacon('/api/track', JSON.stringify({
  aid, name: 'article_click', props: { id, position: 3 }, path: location.pathname
}));
```

后端一张表：

```sql
CREATE TABLE events (
  id INTEGER PRIMARY KEY,
  aid TEXT,              -- 匿名标识
  name TEXT,             -- page_view / article_click / question_click / chat_sent
  props TEXT,            -- JSON
  path TEXT,
  referrer TEXT,
  created_at TEXT
);
```

### 12.3 第一版只埋 4 个事件

| 事件 | 什么时候发 | 能回答什么问题 |
|---|---|---|
| `page_view` | 打开首页 | 今天有多少人来看 |
| `article_click` | 点标题去原文 | 内容有没有吸引力（人均读几篇） |
| `question_click` | 点某个问题 | **核心功能的吸引力** |
| `chat_sent` | 发出对话 | 从"好奇"到"真用"的转化 |

订阅和付费单独记（`subscribe`、`paid`），因为涉及身份。

### 12.4 第一版要不要做？

**要做，但只做半天的工作量。**

理由：

- 没有数据，你判断不了"内容好不好"——只能凭感觉
- 判断"内容好不好、付费点设计对不对"，只能靠数据
- 有了 4 个事件，就能算出三个关键指标

**不要做的：**

- ❌ Google Analytics / 百度统计：国内不稳、数据出境合规风险、自定义事件难用
- ❌ 完整的漏斗看板：第一版用不上
- ❌ 用户画像/路径分析：样本太小，没有统计意义

### 12.5 每周只看三个数

```
① 次日留存：今天来的人，明天还来吗？（目标 > 20%）
② 人均阅读：一次打开读几篇？（目标 > 2.5 篇）
③ 对话转化：多少比例的人点了问题？（目标 > 15%）
```

一个脚本每周跑一次，输出一张表，够用了。

### 12.6 隐私合规

- 采集匿名 ID，**不采集手机号、微信、IP 完整地址**
- 隐私政策里写一句："我们使用匿名标识统计使用情况，不收集个人身份信息"
- 埋点数据只用于产品改进，不对外提供

## 十三、开发顺序（施工图）

### 13.1 排期的三条原则

1. **存储改造必须最先做** —— 埋点、订阅、登录全都要写数据库，它是一切的地基
2. **先能跑，再能看，再能收钱** —— 顺序不能反
3. **每个阶段都有可验收的产物** —— 做完就能给别人看

### 13.2 四个阶段

```
阶段 1  能上线（W1–W2）   服务器 + 存储 + 定时    → 3 天不碰电脑也有更新
阶段 2  能看数据（W3）    埋点 + 周报 + 公众号导出 → 知道谁在看
阶段 3  能分发（W4）      公众号运营工具 + 会员页  → 第一批关注者
阶段 4  能收钱（W5–W6）   登录 + 付费 + 额度      → 能卖会员
```

### 13.3 任务清单

#### 阶段 1：能上线（5 个工作日）

| # | 任务 | 工时 | 依赖 | 谁做 |
|---|---|---|---|---|
| 1.1 | 买服务器（香港 2C2G）+ 域名 + DNS | 0.5 天 | — | **你** |
| 1.2 | Docker + compose + Nginx + HTTPS | 0.5 天 | 1.1 | 我 |
| 1.3 | **JSON → SQLite 迁移** | 1.5 天 | — | 我 |
| 1.4 | 定时任务 `daily.sh` | 0.5 天 | 1.3 | 我 |
| 1.5 | 部署上线 + 灰度验证 | 1 天 | 1.1–1.4 | 我 |
| 1.6 | 监控 + 告警 | 0.5 天 | 1.5 | 我 |

**验收：连续 3 天不碰电脑，早上打开就有 8 篇 + 5 条速览。**

#### 阶段 2：能看数据（3 个工作日）

| # | 任务 | 工时 | 依赖 |
|---|---|---|---|
| 2.1 | 埋点表 + `/api/track` + 4 个事件 | 0.5 天 | 1.3 |
| 2.2 | 周报脚本（留存/人均阅读/对话转化） | 0.5 天 | 2.1 |
| 2.3 | **公众号导出**（edition → 排版好的 HTML） | 1 天 | 1.4 |
| 2.4 | 公众号开号 + 首发（你操作） | 0.5 天 | **你** |
| 2.5 | 互推/社群素材（3 张图 + 文案） | 0.5 天 | 2.3 |

**验收：公众号发出第一篇，后台能看到转化。**

#### 阶段 3：能分发（2 个工作日）

> 邮箱订阅已降级，V1 不做。这一阶段全部围绕公众号。

| # | 任务 | 工时 | 依赖 |
|---|---|---|---|
| 3.1 | 公众号排版导出（一键生成可粘贴的 HTML） | 1 天 | 1.4 |
| 3.2 | 每日发布清单（标题/摘要/问题/封面 一键复制） | 0.5 天 | 3.1 |
| 3.3 | 会员落地页（权益说明 + 价格） | 0.5 天 | — |

**验收：每天早上 5 分钟内把当天内容发到公众号，会员页能看明白买什么。**

**为什么不在这一阶段做邮箱：**

| 理由 | 说明 |
|---|---|
| 中国用户不看邮箱 | 打开率可能不到 5%，等于白干 |
| 公众号已经是触达渠道 | 关注即订阅，不需要第二套系统 |
| 维护成本高 | SPF/DKIM/DMARC、退信、垃圾箱，每周要花时间 |
| 省下的时间更值钱 | 同样的时间用来做内容，涨粉更快 |

**什么时候再考虑邮件：** 当有用户主动问"能不能发到邮箱"超过 10 个人时。

#### 阶段 4：能收钱（3 个工作日）

| # | 任务 | 工时 | 依赖 |
|---|---|---|---|
| 4.1 | 登录（邮箱验证码，无密码） | 1 天 | 3.1 |
| 4.2 | 手动开通 + 订单记录（收款码 → 后台点一下） | 1 天 | 4.1 |
| 4.3 | 额度控制（免费 3 轮/天，会员 20 轮） | 1 天 | 4.1, 4.2 |

**验收：来一个用户付钱，1 分钟能开通。**

### 13.5 一条不能违反的规则

> **每个阶段结束前，不做下一个阶段的事。**

阶段 1 没跑满 3 天自动更新，就不要开始埋点；阶段 2 没有 100 个读者，就不要做付费。

**你是一个人。同时开三条战线，最后一条都完不成。**

### 13.6 什么可以先不做

| 功能 | 为什么可以不做 |
|---|---|
| 微信小程序 | 网页在微信里能打开，够用 |
| 微信登录 | 邮箱验证码足够，省掉开放平台资质 |
| 在线支付 | 前 20 个会员手动收款更快 |
| 评论/点赞 | 没有用户量时是负资产 |
| 搜索 | 每天 8 篇，翻两屏就到底了 |
| 多行业版本 | B 端暂缓，暂时不需要 |
